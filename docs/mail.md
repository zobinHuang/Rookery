# Mail and calendars

Rookery reads the user's mail and calendars through the Mac's own Mail and Calendar, so any account the Mac holds (Gmail, Google Workspace, Outlook.com, Microsoft 365 and Exchange, iCloud, IMAP) is reachable at once, with no app registered anywhere and nothing sent to roost. Code agents reach them through `rookery-mail`, an MCP server; Raven is the only one that does by default.

## How it is read

- **Mail.** Mail's library, `~/Library/Mail/V<n>`, is read in place and read-only: the index database `MailData/Envelope Index` for each message's account, folder, sender, recipients, subject, dates, flags and opening (`MailLibrary`, `MailLibrarySearch`), and each message's `.emlx` file for its text (`MimeMessage`). A message's file is at `<account id>/<folder>.mbox/.../<store>/Data/<digits>/Messages/<id>.emlx`, the digits those of its id over a thousand, last first; a `.partial.emlx` lacks attachments or long parts not yet downloaded. Gmail keeps every message in All Mail and marks the inbox, starred and the rest as labels (the `labels` table), so a message's folder is the first of its mailbox and labels that applies. Junk and trash are left out of searches unless asked for. The schema is Mail's own and undocumented; `rookeryctl mail probe` reports what this Mac's looks like.
- **Accounts.** Mail's scripting names each account's id (which names its directory and its mailboxes' URLs), name and addresses (`MailScripting`), read again every five minutes.
- **Calendars.** EventKit, with full access: every calendar of every account, events between two moments, copies of one meeting on several calendars merged by their shared id (`CalendarLibrary`).

Rookery holds every permission itself: Full Disk Access for Mail's library (granted by the user in System Settings), Calendars, and control of Mail (asked for the first time). `rookery-mail` holds none: it forwards each call to the running app over the control socket (`ControlRequest.mailTool`).

## The tools

`list_accounts`, `search_mail`, `read_mail`, `read_thread`, `list_events` and `list_drafts` (Rookery's drafts) read. `propose_draft`, `propose_event`, `propose_event_change`, `propose_event_removal`, `propose_open_event` and `propose_draft_removal` only check what they are given and return a proposal, which Raven shows as a card, except a draft, which goes straight into Rookery's drafts (`RavenAgent.fileDrafts`) and shows in the conversation only as one line counting the drafts it made, with Open; once the user approves it, Rookery carries it out itself (`MailService.carryOut`): drafts thrown away leave Rookery's drafts, and Mail's go to the trash (`MailDrafts.trash`); an event is added, changed or removed through EventKit, this occurrence only for a recurring one; an invitation opens in Calendar for the user to answer. No tool sends mail, and no agent holds a tool that changes anything. EventKit cannot invite attendees or answer invitations, which is why those go through Mail and Calendar.

Settings shows Mail and Calendars apart. Mail: whether Rookery can read Mail's library, with a way to grant it, whether Mail is running (new mail arrives only while it is), and every mail account, whether Raven may read it and whether it is personal or work. Calendars: whether Rookery may read them, the default calendar, and every calendar account, whether Raven may read and propose changes to it. The default calendar (`defaultCalendarId`) is where an event goes when none is named: `list_accounts` marks it `default`, `propose_event` takes it when given no `calendar_id`, and the calendar page's new event starts on it. Accounts the user holds back in `mail-accounts.json` in the data directory (`MailAccountSettings`: mail by address, calendars by account name) are not seen by any tool.

## Checking it

    .build/debug/rookeryctl mail probe                         # access, the library's shape, the accounts, the calendars
    .build/debug/rookeryctl mail list_accounts
    .build/debug/rookeryctl mail search_mail '{"folder":"inbox","unread_only":true}'
    .build/debug/rookeryctl mail list_events '{"start":"2026-11-17","end":"2026-11-24"}'
    printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | .build/debug/rookery-mail

These read the user's own mail; when checking a change, print counts rather than subjects and text.

## On the stage

The stage's right strip (`RightSidebarView`) holds three buttons, for the calendar, the mail and the mixer, each opening its page in the content area and lit while it shows, a second click closing it: the calendar's shows the next event's time today, the mail's the unread count, the mixer's whether it holds any sound. It shows nothing more, as the pages show it all; the right sidebar hotkey hides the strip or shows it again, and the content area the managed windows are laid in gives up its width (`StageController.contentFrame`). The pages: the calendar (`CalendarPage`: day, week and month, calendars shown or hidden, events the user adds or removes), the mail (`MailPage`: every inbox, unread, flagged, each account's inbox and sent, Rookery's drafts, a search, a reader, and replying, marking read and flagging) and the mixer (`MixerPage`: every strip in a column down the middle); all three are pages of the window switcher. `PersonalDataModel` keeps the strip's badges and the pages current: the calendars on EventKit's change notification and every minute, the mail when Mail writes its library (checked every five seconds) and every half minute. A click on an event on the calendar page shows it in full as a card in the stage's colors (`EventDetailView`) at the page's right, rather than in a popover, which took neither the theme nor a size of its own. On the calendar page an event on a writable calendar can be dragged to a new time, by quarter hours, and across days in the week. On the calendar page's hours, dragging where no event is draws out a slot by quarter hours (`EventSlot`), shown as a dashed block with its time, and letting go opens a new event for it as a card in place of an event's (`NewEventCard`): its title typed at once, the default calendar first, its times to adjust and where it is; Return adds it to the calendar. The mail page's reader shows the message's whole conversation (`MailSource.thread`), oldest first, along a line with a dot for each message, filled while unread: each message is a card with its sender's mark, to whom and when, folded to its opening but for the message chosen and the latest; a click on its head opens or folds it. An open message shows its HTML as sent in a `WKWebView` (`MailHTMLView`) with the message's scripts off and links opened in the browser, as tall as its content, which a script of Rookery's own measures once it is laid out, so the conversation scrolls as one; a message without HTML shows its plain text. The mail page reads a conversation newest first as a chat: each message a bubble (`MailMessageCard`, on `MessageBubbleShape`), the user's own on the right and everyone else's on the left with their mark at its top left and the bubble's tail reaching up to it, the user's with their own mark at its top right once they set themselves down in People, formatted text on its white page shaped as the bubble and plain text in the conversation's bubble colors; every one open until the user folds it to its opening, those in the trash, junk or drafts left out unless chosen, as drafts thrown away while replying, each read from the library as it scrolls into view (a `LazyVStack`) and keeping its own height, so a message laid out redraws only its card; every message's page shares one in-memory website data store and the remote-content rule is compiled once. Mail's accounts, which only its scripting tells, are read once and then again in the background every five minutes while the old list serves, so opening a message never waits on Mail. Every script runs in an `osascript` of its own off the main thread (`MailScripting.run`), so Mail taking its time never stalls the app, and finds a message where Mail keeps it (`MailMessagePlace`: the account's id and the mailbox's path from the library's mailbox URL, and the message's id, which is its row in the library), at once: finding one by its `Message-ID` across the inboxes took Mail over half a minute in a large one. Choosing another message keeps the reader standing, its toolbar included, and dims the conversation until the new one is read, then swaps the conversation alone: tearing the reader down and building it again cost half a second each time. The toolbar names its buttons when the reader is wide enough, read from its width once, not with `ViewThatFits`, which measured it over and over. While the list, a conversation or a message's text is on its way, its shape stands in for it with a light sweeping across (`SkeletonBlock`), a message's page staying hidden until it is laid out. Each card shows only its own words: the earlier mail a reply quotes is taken away (`MailQuote`: in HTML by a script of Rookery's own that cuts at the first quote a client marks, as Gmail's `gmail_quote`, Apple Mail's `blockquote type=cite` or Outlook's `divRplyFwdMsg` and header border, or at an attribution line such as `On … wrote:`, `… 写道：`, `Le … a écrit :` or `Am … schrieb …:`, whether it stands in an element of its own or as a line of text before a `blockquote`, and over a line break; in plain text at the same lines, wrapped over up to three, or a closing run of `>` lines), unless nothing of the message's own would remain, as in a forward; Show Quoted Mail brings it back. A message Mail wrapped as shared, as Rookery's replies were before they went as a signature and as anything a script or Share sends through Mail, reads as its sender's own words: the wrap's `blockquote` loses its `type=cite` before the cut, and plain text quoted throughout loses one level of `>` (`MimeMessage.unquotedAppleShare`). A message chosen in the reader is marked read in Mail once it has stayed open a second, so stepping past one leaves it unread. People are set down in the settings (`PeopleStore`, `people.json` in the data directory with a photo each in `people/`): a name, the addresses their mail comes from, and a photo if given (chosen by clicking their mark, then framed under a round window by dragging and zooming, `PhotoCropper`; the whole picture is kept beside the photo so Adjust can frame it again), else their initials on a color their first address picks (`PersonMark`). Wherever an address is shown, in the sidebar's mail, the mail page's lists and conversation and an event's attendees, the person it belongs to is shown in its place (`AddressLabel`). In Raven's box and the launcher, `@` offers the people first, with their marks, then roost's resources (`MentionTarget`, from `FleetModel.mentionTargets(in:)`), in a list floating over what is shown, in the launcher over its rows or a conversation alike; a person's mention is their name as one word (`@Alex-Chen`), shown in the conversation as their mark and name, and every person a request names is listed for Raven with their addresses. The views read through `MailSource`, which `MailService` implements; the offscreen render gives sample data in its place, so it never scripts Mail.

The mail page writes mail itself and never opens Mail's windows. Every mail being written is a `MailReplyDraft` in Rookery's drafts (`MailDraftStore`, `mail-drafts.json` in the data directory, readable by the user alone, written shortly after each change), listed newest first under Drafts in the folder list; the page's memory keeps only which one is open. Reply adds one and opens it in an editor under the thread (`MailReplyEditor`): from the account the message came to, to its sender, under its subject, every field editable. A draft that answers nothing opens on its own in the reader as a new message, without the Raven column. Send hands it to Mail, which sends it without a window (`MailDrafts.send`), the draft Mail keeps of a scripted message is moved to the trash, and it leaves Rookery's drafts; Discard throws it away. It is written with Mail's own `reply` to the message it answers when Mail finds it, so it stays in its thread (`In-Reply-To` and `References` set by Mail) and quotes that message as Mail quotes any reply, under `On … wrote:` in a `blockquote type=cite` and with `>` in its plain part, which Apple Mail, Gmail and Outlook all fold; otherwise as a new message. What the user wrote goes in as a signature made for that one message and deleted once it is sent: Mail wraps any text a script sets as a message's content in a quote of its own (`setSharedContent` in Mail's compose page, the path a page shared to Mail takes: a `div.Apple-Mail-URLShareWrapperClass` around a `blockquote type=cite`, and `>` before every line of the plain part), so every client showed the user's own words as quoted and their history a level too deep, while a signature it places as written. `html content` does nothing, as Mail's dictionary says, and setting the default message format to plain does not stop the wrap. Mail puts the signature above the quote unless the user chose otherwise in its settings. A draft carries attachments (`MailReplyDraft.listAttachments`, absolute paths, 20 MB at most together): Raven's `propose_draft` takes them as `attachments`, checked to exist, and the editor adds them with Attach…, Paste (files or an image on the clipboard, an image kept as a PNG under `mail-attachments` in the data directory) or a drop of files or images, each shown as a chip with its size to take off. Mail adds them to the message's content after the signature, which it can only do the way a shared page goes in: it places them above the text, in the share wrap, and drops a reply's quote of the message it answers, so a reply with attachments goes without the quote, still in its thread. Ask Raven opens a column at the page's right (`MailRavenPanel`, hidden until shown): the thread's conversations with Raven (`RavenConversation.mailMessageId`, found from any message of the thread), the latest shown unless another is picked from its menu or a new one started, the choice kept per thread in the page's memory, its first request telling Raven which mail it is about and to propose the reply as a draft once the user is happy with it. The draft it proposes goes into Rookery's drafts and opens in the editor under the thread. In the reader, plain text that quotes is drawn as quoted (`MailQuote.passages`): each level of quoting under a bar of its own, its `>` marks taken off.
