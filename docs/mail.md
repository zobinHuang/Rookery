# Mail and calendars

Rookery reads the user's mail and calendars through the Mac's own Mail and Calendar, so any account the Mac holds (Gmail, Google Workspace, Outlook.com, Microsoft 365 and Exchange, iCloud, IMAP) is reachable at once, with no app registered anywhere and nothing sent to roost. Code agents reach them through `rookery-mail`, an MCP server; Raven is the only one that does by default.

## How it is read

- **Mail.** Mail's library, `~/Library/Mail/V<n>`, is read in place and read-only: the index database `MailData/Envelope Index` for each message's account, folder, sender, recipients, subject, dates, flags and opening (`MailLibrary`, `MailLibrarySearch`), and each message's `.emlx` file for its text (`MimeMessage`). A message's file is at `<account id>/<folder>.mbox/.../<store>/Data/<digits>/Messages/<id>.emlx`, the digits those of its id over a thousand, last first; a `.partial.emlx` lacks attachments or long parts not yet downloaded. Gmail keeps every message in All Mail and marks the inbox, starred and the rest as labels (the `labels` table), so a message's folder is the first of its mailbox and labels that applies. Junk and trash are left out of searches unless asked for. The schema is Mail's own and undocumented; `rookeryctl mail probe` reports what this Mac's looks like.
- **Accounts.** Mail's scripting names each account's id (which names its directory and its mailboxes' URLs), name and addresses (`MailScripting`), read again every five minutes.
- **Calendars.** EventKit, with full access: every calendar of every account, events between two moments, copies of one meeting on several calendars merged by their shared id (`CalendarLibrary`).

Rookery holds every permission itself: Full Disk Access for Mail's library (granted by the user in System Settings), Calendars, and control of Mail (asked for the first time). `rookery-mail` holds none: it forwards each call to the running app over the control socket (`ControlRequest.mailTool`).

## The tools

`list_accounts`, `search_mail`, `read_mail`, `read_thread`, `list_events` and `list_drafts` (Rookery's drafts) read. `propose_draft`, `propose_event`, `propose_event_change`, `propose_event_removal`, `propose_open_event` and `propose_draft_removal` only check what they are given and return a proposal, which Raven shows as a card, except a draft, which goes straight into Rookery's drafts (`RavenAgent.fileDrafts`) and shows in the conversation only as one line counting the drafts it made, with Open; once the user approves it, Rookery carries it out itself (`MailService.carryOut`): drafts thrown away leave Rookery's drafts, and Mail's go to the trash (`MailDrafts.trash`, found in its drafts mailbox by `Message-ID`); an event is added, changed or removed through EventKit, this occurrence only for a recurring one; an invitation opens in Calendar for the user to answer. No tool sends mail, and no agent holds a tool that changes anything. EventKit cannot invite attendees or answer invitations, which is why those go through Mail and Calendar.

Settings shows Mail and Calendars apart. Mail: whether Rookery can read Mail's library, with a way to grant it, whether Mail is running (new mail arrives only while it is), and every mail account, whether Raven may read it and whether it is personal or work. Calendars: whether Rookery may read them, the default calendar, and every calendar account, whether Raven may read and propose changes to it. The default calendar (`defaultCalendarId`) is where an event goes when none is named: `list_accounts` marks it `default`, `propose_event` takes it when given no `calendar_id`, and the calendar page's new event starts on it. Accounts the user holds back in `mail-accounts.json` in the data directory (`MailAccountSettings`: mail by address, calendars by account name) are not seen by any tool.

## Checking it

    .build/debug/rookeryctl mail probe                         # access, the library's shape, the accounts, the calendars
    .build/debug/rookeryctl mail list_accounts
    .build/debug/rookeryctl mail search_mail '{"folder":"inbox","unread_only":true}'
    .build/debug/rookeryctl mail list_events '{"start":"2026-11-17","end":"2026-11-24"}'
    printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | .build/debug/rookery-mail

These read the user's own mail; when checking a change, print counts rather than subjects and text.

## On the stage

The stage's right sidebar (`RightSidebarView`) has three tabs: today's calendar (`TodayCalendarView`: the next event with a button to join its meeting, the all-day events, the day's hours with overlapping events side by side and a line at now), the unread mail of every inbox (`UnreadMailView`), and the mixer, which used to be a mode of the left sidebar. It folds to a strip of the three icons, showing the next event's time and the unread count, and the content area the managed windows are laid in gives up its width either way (`StageController.contentFrame`). Its expand buttons open the calendar page (`CalendarPage`: day, week and month, calendars shown or hidden, events the user adds or removes) and the mail page (`MailPage`: every inbox, unread, flagged, each account's inbox and sent, Rookery's drafts, a search, a reader, and replying, marking read and flagging); both are pages of the window switcher. `PersonalDataModel` keeps the sidebar current: the calendars on EventKit's change notification and every minute, the mail when Mail writes its library (checked every five seconds) and every half minute. The sidebar's tabs are Schedule, Mails and Mixer. Mails has a tab for every inbox's unread mail together, then one per account by its full address, wrapping onto more lines as needed, listing its unread mail above its read mail, each a page at a time (`MailQuery.offset`, `isReadOnly`). A click on an event, in the sidebar or on the calendar page, shows it in full as a card in the stage's colors (`EventDetailView`): over the sidebar's hours, or at the page's right, rather than in a popover, which took neither the theme nor a size of its own. On the calendar page an event on a writable calendar can be dragged to a new time, by quarter hours, and across days in the week. On the sidebar's hours and on the calendar page's, dragging where no event is draws out a slot by quarter hours (`EventSlot`), shown as a dashed block with its time, and letting go opens a new event for it as a card in place of an event's (`NewEventCard`): its title typed at once, the default calendar first, its times to adjust and where it is; Return adds it to the calendar. The mail page's reader shows the message's whole conversation (`MailSource.thread`), oldest first, along a line with a dot for each message, filled while unread: each message is a card with its sender's mark, to whom and when, folded to its opening but for the message chosen and the latest; a click on its head opens or folds it. An open message shows its HTML as sent in a `WKWebView` (`MailHTMLView`) with the message's scripts off and links opened in the browser, as tall as its content, which a script of Rookery's own measures once it is laid out, so the conversation scrolls as one; a message without HTML shows its plain text. The mail page reads a conversation newest first as a chat: each message a bubble (`MailMessageCard`, on `MessageBubbleShape`), the user's own on the right and everyone else's on the left with their mark at its top left and the bubble's tail reaching up to it, the user's with their own mark at its top right once they set themselves down in People, formatted text on its white page shaped as the bubble and plain text in the conversation's bubble colors; every one open until the user folds it to its opening, those in the trash, junk or drafts left out unless chosen, as drafts thrown away while replying, each read from the library as it scrolls into view (a `LazyVStack`) and keeping its own height, so a message laid out redraws only its card; every message's page shares one in-memory website data store and the remote-content rule is compiled once. Mail's accounts, which only its scripting tells, are read on the main thread once and then again in the background every five minutes while the old list serves, so opening a message never waits on Mail. Choosing another message keeps the reader standing, its toolbar included, and dims the conversation until the new one is read, then swaps the conversation alone: tearing the reader down and building it again cost half a second each time. The toolbar names its buttons when the reader is wide enough, read from its width once, not with `ViewThatFits`, which measured it over and over. While the list, a conversation or a message's text is on its way, its shape stands in for it with a light sweeping across (`SkeletonBlock`), a message's page staying hidden until it is laid out. Each card shows only its own words: the earlier mail a reply quotes is taken away (`MailQuote`: in HTML by a script of Rookery's own that cuts at the first quote a client marks, as Gmail's `gmail_quote`, Apple Mail's `blockquote type=cite` or Outlook's `divRplyFwdMsg` and header border, or at an attribution line such as `On … wrote:`, `… 写道：`, `Le … a écrit :` or `Am … schrieb …:`, whether it stands in an element of its own or as a line of text before a `blockquote`, and over a line break; in plain text at the same lines, wrapped over up to three, or a closing run of `>` lines), unless nothing of the message's own would remain, as in a forward; Show Quoted Mail brings it back. People are set down in the settings (`PeopleStore`, `people.json` in the data directory with a photo each in `people/`): a name, the addresses their mail comes from, and a photo if given (chosen by clicking their mark, then framed under a round window by dragging and zooming, `PhotoCropper`; the whole picture is kept beside the photo so Adjust can frame it again), else their initials on a color their first address picks (`PersonMark`). Wherever an address is shown, in the sidebar's mail, the mail page's lists and conversation and an event's attendees, the person it belongs to is shown in its place (`AddressLabel`). In Raven's box and the launcher, `@` offers the people first, with their marks, then roost's resources (`MentionTarget`, from `FleetModel.mentionTargets(in:)`), in a list floating over what is shown, in the launcher over its rows or a conversation alike; a person's mention is their name as one word (`@Alex-Chen`), shown in the conversation as their mark and name, and every person a request names is listed for Raven with their addresses. The views read through `MailSource`, which `MailService` implements; the offscreen render gives sample data in its place, so it never scripts Mail.

The mail page writes mail itself and never opens Mail's windows. Every mail being written is a `MailReplyDraft` in Rookery's drafts (`MailDraftStore`, `mail-drafts.json` in the data directory, readable by the user alone, written shortly after each change), listed newest first under Drafts in the folder list; the page's memory keeps only which one is open. Reply adds one and opens it in an editor under the thread (`MailReplyEditor`): from the account the message came to, to its sender, under its subject, every field editable. A draft that answers nothing opens on its own in the reader as a new message, without the Raven column. Send hands it to Mail, which sends it without a window (`MailDrafts.send`), the draft Mail keeps of a scripted message is moved to the trash, and it leaves Rookery's drafts; Discard throws it away. It is written with Mail's own `reply` to the message it answers when that is in an inbox, so it stays in its thread (`MailDrafts.write`), otherwise as a new message; under what the user wrote goes the message it answers, as Outlook writes it (`MailQuote.reply`): a header of who sent it, when, to and copied to whom and its subject, then the message whole as it was, its own history below it the same way, its trailing spaces and runs of blank lines tidied, since Mail's own quote is not there for a reply made without its window, and the reader hiding quotes is only how Rookery shows mail. Ask Raven opens a column at the page's right (`MailRavenPanel`, hidden until shown): the thread's conversations with Raven (`RavenConversation.mailMessageId`, found from any message of the thread), the latest shown unless another is picked from its menu or a new one started, the choice kept per thread in the page's memory, its first request telling Raven which mail it is about and to propose the reply as a draft once the user is happy with it. The draft it proposes goes into Rookery's drafts and opens in the editor under the thread. In the reader, plain text that quotes is drawn as quoted (`MailQuote.passages`): each level of quoting under a bar of its own, its `>` marks taken off.
